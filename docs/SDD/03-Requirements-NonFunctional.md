# 03. Нефункциональные требования

Идентификаторы `N-x` ссылаются из задач (`12-VibeCoding-TaskPlan.md`) и тест-плана (`08`).

## N-1. Производительность UI
- Холодный запуск до готовности первой панели: ≤ 1.5 с на Apple Silicon (типично ≤ 1.2 с).
- Открытие каталога 10 000 записей: ≤ 300 мс P95; дифф-обновление (FSEvents, ≤ 100 изменённых записей) ≤ 100 мс.
- Прокрутка панели 50 000 строк: стабильные 60 fps (no hitching > 2 кадров).
- UI-поток никогда не вызывает блокирующий диск/сеть: правило MainActor-only для VFS-операций; всё дисковое — в фоновых очередях/акторах.

## N-2. Память
- Idle (две панели, каталоги по 100 записей): < 150 MB RSS.
- Панель с 100 000 строк: + ≤ 100 MB (обязательны lazy-атрибуты, без инстанцирования ячеек для всех строк).
- Просмотр файла любого размера не буферизует его в память (стрим-окно 2–8 MB).

## N-3. Пропускная способность копирования
- Копирование на томе с clonefile («копия» tức-мтовенно) ≤ 100 мс на файл + metadata.
- Копирование больших файлов (≥ 1 GB) — не менее 90 % скорости `cp -R` на том же железе (fcopyfile, 1–4 MB буферы, параллелизм на уровне файлов).
- Параллелизм: копирование N файлов использует до 4 concurrent-потоков, не деградируя отзывчивость очереди.

## N-4. Надёжность операций с файлами
- Никогда нет pérdida данных без явного подтверждения: перезапись — только через диалог конфликтов.
- Атомарность per-file: temp-файл + rename; прерванное копирование не оставляет «половинок» с целевым именем.
- Move/mkdir/rename логируются в Operation Journal; отчёт операции: ok/skip/fail с причинами errno (переводимыми).
- Кросс-томные операции матрично тестируются (см. `08`), включая exFAT/HFS+/SMB.

## N-5. Стабильность
- Crash-free sessions ≥ 99.5 % (пост-релейз цель); сейчас — zero known reproducible crashes в core-flow.
- Любая ошибка пользователю — человеко-читаемая + «Показать детали» с errno/stack; raw panic запрещён (fatalError только в Preconditions на инвариантах).

## N-6. Тестируемость
- Покрытие по модулям (logик lines): DomainKit ≥ 90 %, VFSKit ≥ 80 %, FileOpsKit ≥ 85 %, EnginesKit ≥ 80 %.
- All engine-модули исполняются в тестах без реального UI и без сетевых реальных серверов (in-memory fake-адаптеры).

## N-7. Локализация
- EN + RU с первого релиза; все строки — String Catalogs; проверка «нет хардкод-строк» в CI (grep-правило).
- Даты/числа/размеры — locale-aware; сортировка — locale-aware ( пробел/регистр правилом à la Finder).

## N-8. Доступность
- VoiceOver: панели и диалоги объявляют имя/тип/выделение; обозначения «COPIES TO panel B» читаются.
- Follow system: increased contrast, reduced motion; keyboard nav полная (без трэкинга мышь-только flow).

## N-9. Приватность и безпасность
- Пароли — только Keychain (kSecAttrAccessibleAfterFirstUnlock); в настройках/логах никогда не выводятся.
- Никакой сетевой активности except явно запросанной (SFTP-сессии, проверка обновлений пользователем).
- Дистрибуция: signed + notarized; автообновление Sparkle c EdDSA-подписью; хостом обновлений — GitHub Releases (или собственный JSON feed).

## N-10. Лицензионная чистота (GPL-3.0-or-later)
- Third-party в обязательном порядке пермиссивные: MIT / Apache-2.0 / BSD (текущий список: см. `11` и research/02). Примеры: ZIPFoundation (MIT), swift-nio-ssh (Apache-2.0), Citadel (MIT), SwiftTerm (MIT), AMSMB2 (MIT), SWCompression (MIT), Sparkle (MIT).
- Каждый файл решения — SPDX header; LICENSE (GPL-3.0) + NOTICE с полным списком вендоров и лицензий; CI-задача проверяет отсутствие запрещённых лицензий в Package.resolved.
- RAR-код: не включать (лицензионные ограничения unrar); зафиксировать в readme и `10-Risks`.

## N-11. Совместимость ОС
- Deployment target macOS 14; собирается на актуальном Xcode SDK; по мере новых_MAJOR OS — обновление без слома публичного API (тесты совместимости).
- Уважать стабильность API AppKit: никаких приватных API; workaround-ы помечены TODO+issue.

## N-12. Инженерная база
- Сборка: SPM-модули; инкрементальная сборка < 60 с; CI GitHub Actions: build + test (macOS runner) + lint (SwiftFormat/SwiftLint) + SBOM-license check.
- Логи движка: os.Logger с категориями (vfs/fileops/ui/terminal); «Экспорт диагностики» в settings (лог-архив без чувствительных имён: фильтрация путей до `~/…`).
